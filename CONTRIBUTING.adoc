= Contributing to pixterm

== Tools

* Clang 19 or later, with libc++ and, on Linux, the lld linker
* CMake 3.28 or later, and Ninja
* Docker, for `tools/ci.sh` (colima works on macOS)

The core library and its tests build on macOS with Apple's Clang. The
programs that use X11 build only on Linux; use the toolchain container
for those.

== Presets

[cols="1,3"]
|===
| Preset | Builds

| `debug` | debug build with tests
| `ci` | debug build, warnings as errors
| `sanitize` | debug build with the address and undefined-behaviour sanitizers
| `analysis` | debug build checked by clang-tidy
| `fuzz` | the libFuzzer targets
| `release` | optimized build without tests, as the image uses
|===

[source,sh]
----
cmake --workflow --preset ci    # configure, build and test in one step
----

== Checks

`tools/ci.sh` runs, in a Debian container with the same toolchain the
image uses:

* `format`: clang-format finds no change to make
* `ascii`: every file is plain ASCII
* `reuse`: every file states its copyright and licence
* `build`: warnings as errors, then the unit tests
* `sanitize`: the unit tests under ASan and UBSan
* `analysis`: clang-tidy, warnings as errors

Name steps to run only those: `tools/ci.sh build sanitize`. GitHub
Actions runs the same script on every push and pull request.

== Writing code

* Write the test first. Each `TEST` in `tests/` is a separate CTest
  test named after its suite and case.
* Errors are values. Return `std::expected` or `std::optional`; never
  throw. pixterm builds with `-fno-exceptions`, because exceptions
  cannot pass through the C callbacks of Xt, Motif and libc.
* Untrusted input (settings, files from a USB drive, network packets)
  is checked by the functions in `include/pixterm/validate.hpp` before
  use, and every parser of it has a fuzzer.
* Own every resource with a type that releases it: file descriptors,
  child processes, X resources.
* Names: types in `CamelCase`, everything else in `snake_case`,
  private members with a trailing `_`. clang-format and clang-tidy
  check the rest.

== Comments

* Every file starts with two SPDX lines:
+
[source,cpp]
----
// SPDX-FileCopyrightText: 2026 Chris Mecca
// SPDX-License-Identifier: MIT
----
+
Files that cannot hold a comment are listed in `REUSE.toml`. Git
records who changed what and when, so files carry no other banner.
* `///` documents an interface for its callers: what it does, what it
  needs, what it returns, who owns what and how it fails. A non-trivial
  file may start with a `/// @file` paragraph.
* `//` in an implementation explains why, never what.
* `// TODO(#123):` names the issue that tracks the work.

== Writing documents

Documents are AsciiDoc. Write them as Orwell asked:

. Never use a figure of speech you are used to seeing in print.
. Never use a long word where a short one will do.
. If it is possible to cut a word out, cut it out.
. Never use the passive where you can use the active.
. Never use a foreign phrase, a scientific word or jargon if there is
  an everyday English equivalent. Write "for example", not "e.g.".
. Break any of these rules sooner than say anything outright barbarous.

Every file is plain ASCII.

== Commits

One change per commit, with a message that says what changed and why
in the imperative: "Add serial console hosts", not "Added".
