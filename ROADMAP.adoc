= pixterm roadmap

0.9 does everything the first version of pixterm did: SSH, XDMCP,
terminal, direct X, rexec and rsh, VNC, RDP and serial console
sessions, on a read-only Raspberry Pi image. 1.0 adds the other ways an
X terminal reached hosts in the 1990s, and most of the terminal features
an NCD offered. 1.2 adds the devices that hosts use, and several hosts
at once on one display. After 1.2, pixterm takes fixes, not features.

Sizes: S is up to a day, M a few days, L a week or more. The numbers
are kept from the first plan so that issues can refer to them.

== Decisions

[cols="1,3",options="header"]
|===
| Question | Answer

| Devices | A host reaches the terminal's devices only during its own session, and only those its host entry allows. SSH sessions carry them through the session's connection; for other sessions, a packet filter opens a port to that host alone.
| Screen lock | Unlocks with a code chosen when locking. It sends nothing to the host and keeps no account password.
| USB drives | Files are copied over SFTP; the host never gets the device.
| Sound | The PulseAudio protocol through SSH sessions; NAS, the successor of NCDaudio, for XDMCP and direct X hosts.
| Dropped | Network boot, and settings kept on a central server.
|===

== Also wanted for 1.0

* IPv6 host addresses, tested from end to end
* Sun and DEC keyboards, with the DEC LK201 editing keys for OpenVMS
* Diagnostics saved to a USB drive for bug reports
* Time zone and NTP server settings (the Pi has no clock battery)
* Issue templates for bug reports and host reports
* A table of host systems and protocols known to work

== Not planned

Images for x86 thin clients or NetBSD; updates to a second system
partition; Inferno, SPICE and X2Go. LAT: Debian no longer has latd, a
root daemon on raw Ethernet; OpenVMS hosts and DECservers keep SSH,
Telnet and XDMCP.
